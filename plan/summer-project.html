ACADEMIC ROADMAP

每个阶段只增加一层能力

先让服务稳定地保存和分析文档，再做检索；先让单 Agent 可靠运行，再接 MCP。所有版本都在同一仓库中演进，形成真实的项目迭代记录。

v0大一暑假

文档处理后端

先建立 AI 应用的后端底座，不做 RAG。

  • Python async、FastAPI、Pydantic、pytest。
  • PostgreSQL、Redis、BackgroundTasks。
  • 云端 LLM 摘要、关键词、分类。
  • Docker Compose 与服务器部署。
交付：Document Assistant API v0
v1大二上

RAG 知识库

把已保存的文档升级为可检索的知识来源。

  • Loader、清洗、文本切分与 metadata。
  • Embedding、pgvector、相似度检索。
  • Top-k、过滤、基础 rerank 与引用来源。
  • 问答集、Bad Case 与检索效果记录。
交付：带来源的 /chat RAG 问答
v2大二寒假

  • Checkpointer、thread_id 与 PostgreSQL 恢复。
  • interrupt 审批、流式状态和单 Agent 评估。
交付：可恢复的知识库 Agent 服务

WHAT YOU ARE BUILDING

当前在做 v0：后续 RAG 的文档处理底座

用户录入文档后，系统保存原文，后台调用模型生成摘要、关键词与分类。它先解决后端工程问题；RAG 分块与检索会在 v0 稳定后接入同一项目。

用户能做什么

保存文档，等待分析，查询结构化结果

  • 录入文本，后续再逐步加入文件上传。
  • 后台任务调用模型完成摘要、关键词和分类。
  • 把结果和任务状态持久化并提供查询接口。
  • 用 Redis 缓存高频文档查询。
本次不做什么

不把 v0 做成无边界的平台

  • 不训练或微调模型，只用云端 API。
  • 不做多 Agent、MCP、复杂权限系统。
  • 不做 Embedding、向量库、RAG 分块和检索。
  • 不追求所有文件格式，先稳定支持文本录入。
1文档入库保存原文与 metadata
2创建后台任务pending / processing
3云端模型分析摘要 + 关键词 + 分类
4保存并查询结果 + Redis 缓存

LEARN AND BUILD

大一暑假：六个阶段完成 v0

每个阶段都包含要学的内容、立刻要写的代码和离开该阶段前的完成标准。先完成当前阶段，再进入下一项。

阶段 01

FastAPI 与 HTTP

  • 学习路由、状态码、请求/响应模型与 Swagger。
  • 理解 async def、await、超时和非阻塞请求。
  • 写 GET /health 与内存版文档 CRUD。

完成后：浏览器可在 /docs 调用 API。

阶段 02

项目结构与测试

  • 拆分 API、Schema、Service、Database 和测试目录。
  • 学习 Pydantic 校验、统一异常与环境变量读取。
  • 为一个函数和两个接口编写 pytest。

完成后：代码不再全堆在 main.py。

阶段 03

PostgreSQL 与数据

  • 创建文档与分析结果两张表，练习 CRUD、索引与事务。
  • 使用 SQLAlchemy 保存和读取数据。
  • 只学项目需要的 SQL，不刷高级数据库架构。

完成后：重启 API 后文档仍然存在。

阶段 04

Redis 与后台处理

  • 用 Redis 缓存文档详情或列表，并设置 TTL。
  • 用 BackgroundTasks 模拟处理状态：等待、处理中、完成、失败。
  • 文档分析不能阻塞普通查询接口。

完成后：能查询异步任务状态。

阶段 05

云端 LLM 分析

  • 调用兼容 OpenAI 格式的云端模型。
  • 用 Pydantic 获取摘要、关键词和分类的结构化结果。
  • 查看一次 LangSmith trace，处理模型失败与超时。

完成后：文档可生成可查询的分析结果。

阶段 06

Docker 与服务器运行

  • 编写 Dockerfile 和 Docker Compose，启动 API、PostgreSQL 与 Redis。
  • 在本机启动 API、PostgreSQL 与 Redis。
  • 把同一套 Compose 部署到你的 Linux 服务器。

完成后：他人可按 README 复现项目。

API CONTRACT

接口先少而完整

先只支持 title + content。保存后发起异步分析，结构化结果可查询；文件解析、分块与问答会在后续 RAG 迭代再加入。

方法路径用途最小请求或返回
GET/health健康检查{"status":"ok"}
POST/documents创建文档{"title":"...","content":"..."}
GET/documents文档列表支持 limit 与 offset
GET/documents/{id}文档详情优先从 Redis 读取缓存
DELETE/documents/{id}删除文档同步清理对应缓存
POST/documents/{id}/analyze发起异步分析返回 task_id
GET/tasks/{task_id}查询任务状态pending / processing / completed / failed
GET/documents/{id}/analysis获取分析结果摘要、关键词、分类、模型名

RUN LOCALLY AND REMOTELY

你的服务器可以运行它

前提是服务器为 Linux、拥有 SSH 与 Docker 权限，并允许开放应用端口。项目使用云端模型，不需要 GPU。

本地开发

  1. 创建项目与 Python 虚拟环境，准备 .env。
  2. 用 Docker Compose 先启动 PostgreSQL 和 Redis。
  3. 运行 FastAPI，访问 http://127.0.0.1:8000/docs。
  4. 先用 Swagger 手动验证接口，再运行 pytest。
cp .env.example .env
docker compose up -d postgres redis
uvicorn app.main:app --reload
pytest

Linux 服务器

  1. SSH 登录，确认 Docker 与 Docker Compose 可用。
  2. 克隆仓库，在服务器写入真实的 .env。
  3. 使用 Compose 后台构建并启动，开放 API 或反向代理端口。
  4. 用 docker compose logs -f 查看日志，用 /health 验证。
git clone <your-repo-url>
cd document-assistant-api
cp .env.example .env
docker compose up -d --build
docker compose ps
服务器上线前检查不要提交 API Key；数据库与 Redis 不暴露公网；安全组仅开放必要端口；配置强密码；先用 IP + 非敏感测试文档验证，再接入域名和 HTTPS。
